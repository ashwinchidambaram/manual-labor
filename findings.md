# Findings & Decisions

## Requirements (from SPEC.md + CLAUDE.md, 2026-10-28)
- Build "Manual Labor" (`manuallabor` package, `labor` CLI): document → KB zip (Markdown articles + images/ + manifest.json) with a human-in-the-loop review loop.
- v1 inputs: born-digital PDF, scanned PDF (OCR), DOCX. Out: HTML ingest, chat/retrieval, multi-tenant, KB adapters.
- Pipeline: ingest → parse (two parsers, always) → score → group → [HIL scope] → clean+attach → score → [HIL verify ⇄ agent pass] → assemble → export.
- Hard invariant: faithfulness. Cleanup is lossless normalization only; deterministic alignment check (§5.2) always runs; numbers never change silently.
- Priorities in order: faithfulness, reviewer time, portability (local Ollama/vLLM/llama.cpp or Anthropic/OpenAI-compatible APIs).
- 12 build modules (0–11) with gates; module N+1 may not start until N's gate is recorded in docs/PROGRESS.md with the proving command output.
- Subagent pattern per module: design → implement → review (fresh agent, not the implementer) → fix. UI modules add a Playwright UX-check agent.
- Orchestrator must itself run: `uv run pytest -q`, `uv run labor check ./tests/fixtures/project-a`, `--live` variant, `npm test`, `npm run e2e`.
- User direction (2026-10-28): use /planning-with-files; delegate to Opus / Sonnet / Haiku subagents with properly scoped briefs; real verification tests, not "should work".

## Technical Decisions
| Decision | Rationale |
|----------|-----------|
| Fixtures are generated by construction (reportlab + python-docx) with ground-truth JSON emitted by the same generator, deterministic (fixed seed, fixed PDF metadata/dates so sha256 is stable) | Only way to get complete, parser-independent ground truth for all blocks + figures; "hand-written" intent = truth independent of the parsers, which this satisfies. A real public-domain manual can be added later as a 6th, live-only fixture. |
| Fixture set: `clean` (single column, headers/footers, numeric specs, "see Fig. N" refs), `twocol` (two-column), `tables` (table-heavy), `figures` (native raster + vector drawings, duplicated diagram for phash), `scanned` (render `clean` at 300 DPI, add slight skew/noise, re-embed as image-only PDF), `manual.docx` (python-docx with images) | Covers every layout class in SPEC §9 and every gate in CLAUDE.md build order. |
| Parser pair: PyMuPDF (fast, bbox-precise, xref image access) + Docling (layout model, tables). Fallback for parser #2 if Docling install is too heavy/slow on this machine: pdfplumber | SPEC §4.2 says swap freely; keep the adapter interface parser-agnostic. |
| OCR: RapidOCR default (pip, onnxruntime, per-word confidence); Tesseract optional (installed here) | SPEC §10. |
| Provider interface (`manuallabor/providers/base.py`: chat / vision / embed + call log) and a deterministic `MockProvider` are defined in module 0, not module 6 | Modules 4 and 5 need LLM/embeddings before module 6 exists; strict gate order from CLAUDE.md is preserved. MockProvider embeds by hashing tokens → stable clustering in tests. |
| Project state: SQLite (`project.db`) for actions/decisions/jobs + JSON files per stage output on disk | SPEC §10; resumability = every action is a row, every stage output is a file. |
| Frontend types generated with `json-schema-to-typescript` from `schemas/*.json`; command `npm run gen-types`; schema export `uv run labor schemas export` | CLAUDE.md principle 6; names recorded in docs/PROGRESS.md at module 0. |
| Subagent model policy: Opus for designs of core modules and for implementing/reviewing anything on the faithfulness path (3, 5, 10, 11-review); Sonnet for most implementation and UI; Haiku for mechanical scaffolding, CI, type-gen wiring, boilerplate, lint cleanup | User preference + optimized-plan-orchestration scoring. See docs/plans/2026-10-28-manual-labor-build.md. |
| Orchestrator (Fable) runs every gate command itself and writes docs/PROGRESS.md | CLAUDE.md: "A gate is not passed because the code should work; it is passed because the command ran and its output is pasted." |

## Module 1 decisions (2026-10-28, from docs/design/01-parse.md measurements)
| Decision | Rationale |
|---|---|
| OCR engine default = `auto` → Tesseract if the binary is on PATH, else RapidOCR; resolved engine recorded on Document | Design measured Tesseract token F1 0.97–0.997 vs RapidOCR ~0.90 on scanned.pdf, but SPEC §10 wants a pip-only default for portability. `auto` gives both. |
| Use `rapidocr>=3.10` (not `rapidocr-onnxruntime` 1.4, which drops spaces) | Measured. |
| Docling required, offline mode when HF models cached; `MANUALLABOR_REQUIRE_DOCLING=1` makes missing models a failure in the gate | Models already in ~/.cache/huggingface/hub on this machine; warm cost ~0.25 s/page. |
| Scanned pages: two parsers = Tesseract + RapidOCR, Docling layout-only for figure/table regions | PyMuPDF yields nothing on image-only pages. |

## Resource constraint (user flagged 2026-10-28): 16 GB machine
- A Docling-bearing python process (torch) takes ~0.7–1.4 GB RSS; pytest over tests/parse with Docling + OCR + the 200-page stress test reached 1.4 GB. Running two at once (orchestrator full-suite run alongside an implementer's run) was wasteful.
- Rules from now on: the orchestrator does NOT run the full suite while an implementer is running it; slow tests (`-m slow`) run once at the gate; never dispatch two agents that both exercise Docling concurrently; one implementer per module unless their work is non-overlapping and light.

## Module 3 decisions (2026-10-28, from docs/design/03-scoring.md)
| Decision | Rationale |
|---|---|
| Scores live in `docs/<slug>/scores.json`, never rewritten into `blocks.json` | Module 2 fingerprints blocks.json; later modules read via `load_scored_blocks()`. Stage order parse → figures → score; `figures --force` marks score stale. |
| `garbage_ratio` = token-shape rules, no dictionary | Entropy doesn't separate garbage from spec tables (1.42 vs 1.45 vs 2.18 bits); wordlists misfire on part codes/non-English. |
| Reorder allowance is evidence-gated (layout evidence or another parser read that order); sentence swaps need parser evidence; accepted reorder → faithfulness 0.9 | Step order is a fact; SPEC §4.6 "reorder for reading-order fixes" only. |
| Critical set: faithfulness, figure_method always; parser_agreement + textlayer_vs_ocr when numeric or < 0.8; ocr_min when numeric | SPEC §5.3 "single critical failure should dominate". |
| `FaithfulnessResult.numeric_variant` → `numeric_variants: list[NumericVariant]` | A block can have two OCR conflicts. Contract change made in M3 implementation (nothing downstream uses it yet). |
| Module 9: the threshold slider is a **view filter** over the queue; it never re-approves blocks | SPEC "drag to 0 to see everything" conflicts with "≥ threshold = auto-approved"; filtering preserves the audit trail. |
