## IDs

- Document: `<doc-slug>`, lowercase, from the filename or title.
- Block: `b-<doc-slug>-p<page:03d>-<n:02d>`; every parsed block appears in `manifest.json` under `accounting`, either in one article or as `unassigned` with a reason.
- Figure: `FIG-<doc-slug>-p<page:03d>-<n:02d>`, matched by the regex `FIG-[a-z0-9-]+-p\d{3}-\d{2}`.
- Article: `<doc-slug>--<topic-slug>`, or `<doc-slug>` for one article per document.
- Figure references in articles are single lines: `![FIG-ID — caption](images/<doc-slug>/FIG-ID.png)`. The alt text starts with the figure ID, then ` — `, then the original caption (or the generated description, prefixed `[generated]`, when the source has no caption).
- A figure reference line matches the regex `^!\[FIG-[a-z0-9-]+-p\d{3}-\d{2} — .*\]\(images/[a-z0-9-]+/FIG-[a-z0-9-]+-p\d{3}-\d{2}\.png\)$`.
- Every figure reference resolves to an image file and to a `.json` sidecar in the same folder. The same diagram found in several documents is stored once; the other figures point at it and record `duplicate_of` in `manifest.json`.

## How to ingest

1. Read `articles/*.md` (glob). Split each file on the first two `---` lines: the YAML frontmatter, then the Markdown body.
2. Frontmatter keys: `id, title, source_doc, source_file, product_model, pages, sections, figures, blocks, review, generated_at`.
3. `manifest.json` maps article id to file to source blocks and figures.
4. For text-only retrieval use a figure sidecar's `caption_original` and, when you need more, `description_generated` (always machine generated, never source text).
5. The body is source text; Markdown meta-characters in it are not escaped.
